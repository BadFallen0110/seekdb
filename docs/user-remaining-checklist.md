# 你还需要的操作

目标：用大约 15–25 分钟完成真实实验和个人说明。你不必手工编写 JSON，也不必
理解完整代码。

## 第一步：阅读短材料

阅读 [`student-evidence-brief.md`](student-evidence-brief.md)。如果精力不足，只读
第 2、3、5 节，也能完成核心问答。

## 第二步：运行证据采集脚本

在仓库根目录打开 PowerShell，执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\collect-user-evidence.ps1
```

脚本会：

1. 记录当前 commit SHA、时间和操作系统信息。
2. 依次运行 JSONL 协议、强杀恢复、索引回归三个测试。
3. 保存真实命令输出。
4. 提问 5 个短问题，并保存你的原话。
5. 生成 `student-evidence/user-run-时间.md`。

遇到问题时不要修改测试预期。把终端最后 20 行发回即可。

## 第三步：把结果发给我

把生成的 `student-evidence/user-run-时间.md` 整个文件内容发给我。

我会检查：

- 你是否真的运行了命令。
- 输出是否与当前 commit 一致。
- 你的解释是否准确，但不替你改写成“更专业”的内容。
- 哪些回答需要再问一个澄清问题。

## 第四步：可选的一个迁移问题

如果还有一点精力，用两三句话回答：

> 如果另一个系统也有“主表 + 缓存/索引”，你会怎样确保删除时两边同步？

这不是必做项。完成核心 5 个回答后，我会整理 `conversation.json`、真实证据
指针和最终提交说明。

## 不需要你做的事

- 不需要你补写代码。
- 不需要你伪造运行记录。
- 不需要你假装完成隐藏用例。
- 不需要你承诺官方性能满分。
- 不需要你现在点击比赛平台提测。

## 我会在你返回结果后完成

- 把真实实验和回答写入 `conversation.json`。
- 核对每个证据指针和原文片段。
- 更新提交说明、限制和验证记录。
- 跑最终格式检查、测试和 Linux Docker CI。
- 给你一份“是否值得使用唯一提测机会”的明确清单。
