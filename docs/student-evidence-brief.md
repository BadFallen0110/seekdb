# 10 分钟阅读材料

这份材料的目的是让你能够亲自完成 5 个短问题，并真实理解答案。你不需要读完整
实现，也不需要改代码。

## 1. JSONL 协议

数据库启动后先输出：

```json
{"type":"ready"}
```

之后每条请求是一行 JSON，例如：

```json
{"id":1,"op":"execute","sql":"SELECT id FROM docs;","search_mode":"exact"}
```

数据库必须返回一行响应，并保留请求 `id` 的 JSON 类型。BIGINT 必须是 JSON
整数，不能先转成浮点数，否则 `9007199254740993` 会丢失精度。SQL 报错时返回
`ok:false`，但进程继续运行。

## 2. 提交与回滚

- 没有 `BEGIN` 时，每条成功 SQL 自动提交。
- `BEGIN` 后的修改先只在内存中生效，但同一事务内的查询能看到它们。
- `COMMIT` 必须先写 WAL 并同步，才能返回成功。
- `shutdown` 会回滚未提交事务。
- 强杀不会执行任何清理代码，所以已提交数据必须已经在磁盘上。

因此下面两条路径重启后都只应看到已提交的 1：

```text
INSERT 1; BEGIN; INSERT 2; shutdown
INSERT 1; BEGIN; INSERT 2; kill -9
```

## 3. 主表和辅助索引的一致性

VARCHAR 等值查询使用一个辅助索引，索引只保存主键。主表删除记录时，也必须把
辅助索引中的主键删掉。

如果 DELETE 直接删除主表行、却绕过索引维护，那么：

```sql
INSERT (1,'same');
DELETE id=1;
INSERT (1,'same');
```

旧的索引项和新的索引项会同时存在，查询可能返回两次主键 1。

## 4. float32 与失败原子性

向量输入必须是有限 float32，并且维度严格匹配：

- `[1]` 不能写入 `VECTOR(2)`
- `NaN` 和 `Infinity` 非法
- `1e100` 对 float32 溢出，非法
- `16777216` 和 `16777217` 在 float32 中可能相同

非法语句必须在改变表数据或追加有效存储之前失败。

## 5. 性能取舍

当前方案在 `exact` 和 `ann` 模式都使用精确扫描：

- 优点是 Recall@10 = 1.0，过滤和增量维护都容易保证正确。
- 缺点是数据量增加后查询会比真正的 ANN 慢。
- 向量主体分页存储，避免全部常驻内存；标量行元数据仍在内存。
- 批量追加向量减少小 I/O，但如果数据规模继续增长，WAL 恢复成本和标量行内存
  会成为新的限制。

本地性能数据不是官方 cgroup 得分，也不能证明隐藏用例全部通过。
